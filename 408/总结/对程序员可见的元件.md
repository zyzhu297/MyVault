# 408 中的"对程序员可见的元件"

> [!abstract] 一句话总览
> 408 里的"可见"不是物理上看得见，而是**程序员能否通过机器指令直接访问或影响它**；判据只有一条：**它是否属于 ISA 向软件暴露的状态**。由此可得三条主线：**① CPU 寄存器**——通用寄存器、PC、PSW、SP、基址/变址可见；IR、MAR、MDR、暂存寄存器、微程序寄存器不可见。**② 存储层次**——Cache、TLB 对所有人透明；虚拟存储器对应用程序员透明、对系统程序员可见；页表、页表基址寄存器对系统程序员可见。**③ I/O 与微体系结构**——I/O 端口、DMA/中断控制器寄存器对系统程序员可见；设备内部细节、流水线、Cache 替换算法对所有人透明。最容易错的是把 **"透明"当成"看得见"**，以及混淆 **PC/IR、MAR/MDR、TLB/页表**。
> **先分清是谁**：408 默认的"程序员"是**汇编程序员**；**应用程序员**看到的是编译器 + OS 提供的抽象（变量、函数、虚拟地址空间），寄存器/PC/PSW 对他不可见。

> [!note] 先区分：汇编程序员 vs 应用程序员（本文的关键）
> 408 说"对程序员可见"，默认指**汇编（机器级）程序员**——只有他能直接看到并操作 ISA 状态（寄存器、PC、PSW、地址等）。**高级语言应用程序员**面对的是编译器提供的抽象（变量、函数、对象），寄存器由编译器分配，PC/PSW 由运行时和 OS 管理，他并不"看见"这些元件。
> 两者是**编程抽象层级**的区分；"应用程序员 / 系统程序员 / 硬件设计师"则是**职责与权限**的区分，两组维度正交。

## 一、判据：什么叫"对程序员可见"？

> [!tip] 定义（必记）
> **对程序员可见（programmer-visible）**：该元件的状态被 **ISA 明确定义**，程序员可以用机器指令直接读取、写入，或通过指令的执行间接改变它。
> **对程序员透明（transparent）**：该元件的存在和工作过程由硬件（或 OS）自动处理，程序员**不需要、也无法**在指令级直接干预。
>
> 注意：中文教材里的"透明"是**"感觉不到、不用管"**，不是"看得见"。**透明 = 不可见**。

### 1.1 三条判据

| 判据 | 说明 | 例子 |
|---|---|---|
| **① ISA 有没有给它"名字/编号"** | 指令格式能否编码该寄存器，或指令语义是否直接使用它 | 通用寄存器有编号；IR 没有编号，任何指令都不能写 IR |
| **② 程序员是否需要写代码管理它** | 谁写代码管理，它就对谁不透明 | OS 管页表 → 页表对系统程序员可见；Cache 无人管 → 全透明 |
| **③ 出错时谁负责处理** | 硬件自动处理 → 透明；产生异常交 OS → 对系统程序员可见 | Cache 缺失由硬件处理；缺页产生异常交 OS |

> [!important] 一句话口诀
> **"谁需要写代码管它，它就对谁可见。"**
> **汇编程序员**直接面对 ISA 里的寄存器、PC、PSW 和地址；**应用程序员**只在编译器/OS 的抽象层工作（变量、函数、虚拟地址空间）；**系统程序员**还要管页表、TLB 例外、I/O 端口、DMA/中断控制器；**硬件设计师**才管微程序、流水线、Cache 替换算法。

### 1.2 两个正交维度：抽象层级 vs 职责权限

> [!important] 不要混为一谈
> - **按抽象层级分**：高级语言程序员 ↔ 汇编/机器级程序员。
> - **按职责/权限分**：应用开发者 ↔ 系统程序员 ↔ 硬件设计师。
> 同一名系统程序员也可以写汇编；"汇编程序员"强调的是**直接面对 ISA**，不是职位。408 题干里的"应用程序员"通常指**高级语言应用程序员**（写 C/C++/Java 的人）。

| 维度 | 角色 | 能看到/操作的范围 | 典型代表 |
|---|---|---|---|
| 抽象层级 | **高级语言应用程序员** | 变量、表达式、函数、对象、文件、进程/线程、虚拟地址空间；寄存器由编译器分配 | C/C++/Java/Python 业务开发者 |
| 抽象层级 | **汇编程序员（机器级程序员）** | ISA 暴露的寄存器（GPR、PC、PSW、SP、段/基址/变址）、指令、内存地址、寻址方式 | 汇编语言/逆向/嵌入式开发者 |
| 职责/权限 | **系统程序员** | 内核、驱动、编译器后端；控制寄存器、页表、I/O 端口、DMA/中断控制器 | OS 内核开发者、驱动工程师 |
| 职责/权限 | **硬件设计师** | 微体系结构、微程序、Cache/TLB 硬件、流水线 | CPU 设计者 |

> [!tip] 408 题干翻译
> - 问"**对程序员可见的寄存器**" → 默认问**汇编程序员** → 答 GPR、PC、PSW（条件码）、SP 等；IR/MAR/MDR/暂存不可见。
> - 问"**对应用程序员透明**" → 答 Cache、TLB、分页、动态重定位、虚拟存储器。
> - 问"**对系统程序员可见/不透明**" → 答页表、PTBR、I/O 端口、DMA/中断控制器、缺页处理。

### 1.3 汇编程序员 vs 应用程序员：一张表看清

| 对比项              | 汇编程序员                         | 高级语言应用程序员             |
| ---------------- | ----------------------------- | --------------------- |
| 编程对象             | 机器指令、寄存器、内存地址                 | 变量、表达式、函数、对象          |
| 寄存器              | 直接看见并操作 GPR、PC、PSW、SP、段/基址/变址 | 由编译器分配，通常不可见          |
| PC / PSW         | 可见（转移指令、条件码）                  | 不可见（由编译器/硬件管理）        |
| 地址               | 逻辑/虚拟地址、寻址方式；内核态可见物理地址        | 虚拟地址空间中的变量/对象；物理地址不可见 |
| 页表 / TLB / Cache | 页表在用户态不可见；TLB/Cache 透明        | 均透明/不可见               |
| I/O              | 用户态不可直接访问端口；内核态汇编可访问          | 通过系统调用/库函数访问，端口不可见    |
| 异常/中断            | 可写异常处理代码、看到中断向量（内核态）          | 通过语言异常/信号机制间接感知       |
| 典型问题             | "哪些寄存器可见？"                    | "哪些机制对应用透明？"          |

> [!important] 关键结论
> **408 的"可见性"默认站在汇编程序员视角；应用程序员视角看到的是编译器 + OS 提供的抽象。**
> 说"寄存器对应用程序员不可见"并不矛盾——**编译器替它管理寄存器，OS 替它管理 PC/PSW**。本表的"汇编程序员"若未特别说明，指**用户态**汇编程序员；内核态汇编可执行特权指令、访问控制寄存器/端口。

> 出处：[[408/计算机组成原理/1.计算机概述/2.计算机系统层次结构.md|计算机系统层次结构]]（ISA 是软硬件分界面）、[[408/计算机组成原理/3.存储系统/6.虚拟存储器.md|虚拟存储器]]（"谁需要写代码管理它"的透明性辨析）。

## 二、CPU 中的寄存器（计组核心）

### 2.1 对程序员可见的寄存器

| 寄存器 | 可见性 | 可见方式 | 说明 | 出处 |
|---|---|---|---|---|
| **通用寄存器组（GPRs）** | 可见 | 指令中直接编码寄存器号 | 存放操作数、结果、地址；RISC 常 32 个，x86-64 16 个 | [[408/计算机组成原理/5.中央处理器/1.CPU 的功能和基本结构.md\|CPU 基本结构]] |
| **数据寄存器** | 可见 | 指令直接访问 | 存放操作数/结果；x86 的 EAX/EBX/ECX/EDX 与 GPR 合一 | 同上 |
| **地址寄存器** | 可见 | 指令直接访问/寻址方式使用 | 段寄存器 CS/DS/SS/ES、变址 SI/DI、基址 BX/BP | 同上 |
| **堆栈指针（SP）** | 可见 | PUSH/POP、CALL/RET 隐式或显式使用 | 指向栈顶；函数调用/返回依赖它 | 同上 |
| **程序计数器（PC）** | 可见 | 转移/调用指令读取或修改；PC 相对寻址 | 存放下一条指令地址；**能通过指令影响它**，故属于 ISA 可见状态 | 同上 |
| **程序状态字/标志寄存器（PSW/FLAGS）** | **部分可见** | 条件转移指令读取条件码；特权指令修改控制位 | CF/ZF/SF/OF 等条件码可读；IF 等控制位由 CLI/STI 等特权指令修改 | 同上；[[408/计算机组成原理/5.中央处理器/5.异常和中断机制.md\|异常和中断机制]] |
| **累加器（ACC）** | 累加器架构中可见 | 一地址指令隐式使用 | 早期/教学模型中作为运算操作数与结果暂存；GPR 架构中被通用寄存器取代 | [[408/计算机组成原理/5.中央处理器/1.CPU 的功能和基本结构.md\|CPU 基本结构]] |

> [!note] ACC 与 MQ 怎么算？
> ACC、MQ 属于**运算器内部寄存器**：ACC 在累加器架构中可由指令隐式/显式使用，按"可见"处理；MQ 通常只被乘除指令隐式使用，普通指令不能编码它，按 408 教材的可见清单不单列。考试若问"用户可见寄存器"，优先答**通用寄存器、数据寄存器、地址寄存器、PC、PSW（条件码部分）**。

> [!warning] PC 为什么算"可见"？
> PC 不能被普通 `MOV` 随意读写（不同 ISA 规定不同），但**转移、调用、返回、PC 相对寻址**都直接依赖并改变 PC，且 ISA 明确定义其行为。因此教材把它归为**用户可见**。判断标准不是"能不能像 GPR 一样当操作数"，而是**指令语义是否直接使用它**。
> 相对地，**IR 没有任何指令能访问**，所以不可见。

#### PSW 中哪些位可见？

| PSW 位 | 可见性 | 访问方式 |
|---|---|---|
| **CF/ZF/SF/OF/PF/AF**（条件码） | 应用可见（通常只读） | 条件转移、标志读取指令 |
| **IF**（中断允许） | 系统程序员可见 | `CLI`/`STI` 等特权指令 |
| **模式位**（用户态/内核态） | 系统程序员可见 | 中断/异常/陷入时由硬件切换；返回用户态需特权指令 |
| 其他控制/保留位 | 不可见 | 由硬件使用 |

> 结论：**PSW 是"部分可见"寄存器**——条件码对应用可见，控制位只对内核可见。出处：[[408/计算机组成原理/5.中央处理器/5.异常和中断机制.md|异常和中断机制]]；[[408/操作系统/1.计算机系统概述/3.操作系统的运行环境.md|操作系统的运行环境]]。

### 2.2 对程序员不可见的寄存器

| 寄存器 | 归属 | 为什么不可见 | 出处 |
|---|---|---|---|
| **指令寄存器（IR）** | 控制器 | 只存放当前指令，操作码直送译码器；没有指令能读/写 IR | [[408/计算机组成原理/5.中央处理器/1.CPU 的功能和基本结构.md\|CPU 基本结构]] |
| **存储器地址寄存器（MAR）** | 控制器（CPU-主存接口） | 存放访存地址，直接送地址总线；程序员只给出地址值，不直接操作 MAR | 同上 |
| **存储器数据寄存器（MDR）** | 控制器（CPU-主存接口） | 暂存与主存交换的数据；由硬件自动装入/送出 | 同上 |
| **暂存寄存器（A/B、Y、Z、ALUOut）** | 运算器/数据通路 | ALU 输入的锁存、总线冲突隔离、结果暂存，全由控制器微操作驱动 | [[408/计算机组成原理/5.中央处理器/3.数据通路的功能和基本结构.md\|数据通路]] |
| **页表基址寄存器（PTBR/PTR/CR3）** | MMU/系统控制寄存器 | 应用程序员不可见；**对系统程序员可见**（OS 在进程切换时加载） | [[408/计算机组成原理/3.存储系统/6.虚拟存储器.md\|虚拟存储器]]；[[408/操作系统/3.内存管理/1.内存管理概念.md\|内存管理概念]] |
| **微地址寄存器（μPC/CMAR）** | 微程序控制器 | 指向控存中下一条微指令；只对硬件设计者可见 | [[408/计算机组成原理/5.中央处理器/4.控制器的功能和工作原理.md\|控制器]] |
| **微指令寄存器（μIR/CMDR）** | 微程序控制器 | 存放当前微指令；微指令由控存硬件读出 | 同上 |
| **控制存储器（CM）** | 微程序控制器 | 存微程序（ROM）；对程序员完全透明 | 同上 |

> [!note] 页表基址寄存器的"双重身份"
> 它和 MAR 一样都存"地址"，但：
> - **MAR** 存的是**本次访存地址**，是 CPU-主存接口的临时寄存器，**对所有程序员不可见**；
> - **PTBR/PTR/CR3** 存的是**当前进程页表基址**，是 ISA 定义的**系统控制寄存器**，**对系统程序员可见**（OS 用特权指令加载），对应用程序员不可见。
> 408 计组按"用户不可见"归类，操作系统按"内核可见"归类，**两者不矛盾**——参照的程序员层级不同。

### 2.3 微程序控制器的两套寄存器（易混）

| 程序层（机器指令） | 微程序层（微指令） | 区别 |
|---|---|---|
| **PC** | **μPC** | PC 指向**主存**下一条机器指令；μPC 指向**控存**下一条微指令 |
| **IR** | **μIR** | IR 存机器指令；μIR 存微指令；两者是不同层次，无包含关系 |
| **MAR** | **CMAR（μPC 的一种实现）** | MAR 指向主存；CMAR 指向控存；地址空间完全不同 |
| **MDR** | **CMDR（常与 μIR 合并）** | MDR 传主存数据；CMDR 传微指令 |

> [!important] 结论
> 机器指令（程序）**对程序员可见**；微指令/微程序/控存/μPC/μIR **对程序员完全透明**，只有 CPU 设计者（硬件/固件工程师）才关心。
> 出处：[[408/计算机组成原理/5.中央处理器/4.控制器的功能和工作原理.md|控制器]]（程序 vs 微程序、MAR≠μPC、IR≠μIR）。

### 2.4 寄存器可见性速判

> [!tip] 三步判断
> 1. **看指令**：有没有指令能编码它、读它、写它？有 → 可见；没有 → 不可见。
> 2. **看层次**：机器指令层 → 可见；微指令层/硬件层 → 透明。
> 3. **看权限**：汇编程序员在用户态能否访问？能 → 用户态可见；只有内核/驱动能访问 → 系统可见；只有硬件设计者能改 → 透明。
>
> **可见清单**：GPRs、数据寄存器、地址寄存器（段/基址/变址）、SP、PC、PSW（条件码部分）、ACC。
> **不可见清单**：IR、MAR、MDR、暂存寄存器、页表基址寄存器（对应用不可见）、μPC、μIR、CM。

## 三、存储层次中的可见性

> [!abstract] 一句话
> **寄存器与主存是"程序员态"；Cache 与 TLB 是"硬件态"；虚拟存储器是"OS + 硬件"的混合态。**

| 层次/元件 | 可见性 | 对应用程序员 | 对系统程序员 | 说明 | 出处 |
|---|---|---|---|---|---|
| **寄存器** | 可见 | 可见 | 可见 | ISA 定义，指令直接访问 | [[408/计算机组成原理/5.中央处理器/1.CPU 的功能和基本结构.md\|CPU 基本结构]] |
| **Cache** | **完全透明** | 透明 | 透明 | 地址映射、替换、写策略全由硬件完成；无 Cache 地址 | [[408/计算机组成原理/3.存储系统/5.高速缓冲存储器.md\|高速缓冲存储器]] |
| **主存** | 可见 | 可见（虚拟地址） | 可见（物理地址） | 程序以地址访问；主存单元是 ISA 的地址空间 | [[408/计算机组成原理/3.存储系统/1.存储器概述.md\|存储器概述]] |
| **虚拟存储器** | **对应用透明，对系统可见** | 透明 | 可见 | 应用只见虚拟地址；OS 管页表、缺页、置换 | [[408/计算机组成原理/3.存储系统/6.虚拟存储器.md\|虚拟存储器]] |
| **TLB（快表）** | **完全透明**（408 默认） | 透明 | 透明 | 纯硬件查表/回填；软件管理 TLB 的 ISA 属例外 | 同上 |
| **页表/段表** | 对系统程序员可见 | 不可见 | 可见 | 存于主存，OS 建立/维护；应用不知道其存在 | 同上；[[408/操作系统/3.内存管理/1.内存管理概念.md\|内存管理概念]] |
| **页表基址寄存器（PTBR/PTR）** | 系统可见 | 不可见 | 可见 | 进程切换时由 OS 加载 | 同上 |
| **辅存（磁盘/SSD）** | 通过 OS 可见 | 以文件/块设备接口使用 | 可见物理块/驱动细节 | 物理寻址、坏块管理等对应用透明 | [[408/操作系统/5.输入输出管理/3.磁盘和固态硬盘.md\|磁盘和固态硬盘]] |

### 3.1 Cache 为什么是"完全透明"的

- **位置透明**：程序员给的是主存地址，不知道数据在 Cache 的哪一行；Cache 无独立地址空间。
- **管理透明**：映射方式（直接/组相联/全相联）、替换算法（LRU/FIFO/随机）、写策略（写直达/写回）全部由硬件实现。
- **缺失透明**：Cache 缺失由**硬件**检测并自动调入，**不产生异常、不通知 OS**。
- **但性能可见**：命中率影响平均访问时间；程序员可通过数据布局、循环分块等优化局部性，但这不是"直接操作 Cache"。

> [!warning] 透明 ≠ 没有影响
> Cache、TLB、流水线对程序员"不可见"，但它们的**性能后果**是可见的（命中率、流水线停顿影响执行时间）。408 选择题问"程序员是否可见"时答"透明/不可见"；问"是否影响性能"时答"影响"。

### 3.2 虚拟存储器为什么"对应用透明、对系统不透明"

- **应用程序员视角**：只看到连续的虚拟地址空间；页表、页框、缺页处理都由 OS + MMU 完成，程序无需关心。
- **系统程序员视角**：必须建立/维护页表、处理缺页异常、选择页面置换算法、在进程切换时更新页表基址寄存器、管理 TLB（必要时刷新）。
- **硬件视角**：MMU 负责地址转换、缺页检测、权限/越界检查、TLB 查找；但"发现异常"不等于"处理异常"——处理由 OS 完成。

> [!tip] 记忆
> **"要 OS 写代码管理的，就对系统程序员不透明。"**
> Cache/TLB：没人写代码管 → 全透明；
> 虚拟存储器：OS 管页表/缺页 → 对系统程序员可见。
> 出处：[[408/计算机组成原理/3.存储系统/6.虚拟存储器.md|虚拟存储器]]。

### 3.3 TLB vs 页表：一个透明，一个可见

| | TLB | 页表 |
|---|---|---|
| 本质 | 页表项的**硬件 Cache** | 主存中的**数据结构** |
| 管理者 | 硬件（408 默认）；少数 ISA 可由 OS 管理 | OS 建立/维护 |
| 对应用程序员 | 透明 | 不可见 |
| 对系统程序员 | 通常透明（软件管理 TLB 的架构例外） | **可见** |
| 缺失/未命中 | TLB miss → 硬件查页表并回填（或陷入 OS） | 缺页 → 异常交 OS 处理 |

> 出处：[[408/计算机组成原理/3.存储系统/6.虚拟存储器.md|虚拟存储器]]；[[408/操作系统/3.内存管理/2.虚拟内存管理.md|虚拟内存管理]]。

### 3.4 逻辑地址、物理地址与"可见的地址空间"

| 概念 | 谁可见 | 说明 |
|---|---|---|
| **逻辑地址/虚拟地址（VA）** | 应用程序员/汇编程序员 | 程序生成、链接器/编译器使用的地址；页内偏移直接复用 |
| **物理地址（PA）** | 系统程序员/硬件 | 主存实际地址 = 物理页框号 ‖ 页内偏移；应用不可见 |
| **地址转换** | 对应用透明 | MMU 用 TLB/页表完成；应用无需指令参与 |
| **主存地址空间** | 程序员可见 | 由 MAR/地址线位数决定；是 ISA 的一部分 |

> 出处：[[408/计算机组成原理/3.存储系统/6.虚拟存储器.md|虚拟存储器]]、[[408/操作系统/3.内存管理/1.内存管理概念.md|内存管理概念]]。

## 四、I/O 与外设中的可见性

### 4.1 对系统程序员可见的 I/O 元件

| 元件 | 可见方式 | 说明 | 出处 |
|---|---|---|---|
| **I/O 端口（数据/状态/控制寄存器）** | `IN`/`OUT`（独立编址）或 `LOAD`/`STORE`（统一编址） | CPU 通过端口地址访问接口寄存器；状态端口只读、控制端口只写 | [[408/计算机组成原理/7.输入输出系统/2.输入输出接口.md\|输入输出接口]] |
| **I/O 指令** | 通常为特权指令 | 只有内核/驱动能执行；用户态执行会陷入 | 同上；[[408/操作系统/1.计算机系统概述/3.操作系统的运行环境.md\|操作系统的运行环境]] |
| **设备控制器内部寄存器** | 端口地址映射 | 命令字、状态字、数据缓冲；驱动负责编程 | 同上 |
| **DMA 控制器 CSR** | 端口/MMIO | 存放传送方向、内存地址、字节数、模式；OS/驱动初始化 | [[408/计算机组成原理/7.输入输出系统/3.输入输出方式.md\|输入输出方式]] |
| **中断控制器寄存器（IMR/ISR 等）** | 端口/MMIO | 中断屏蔽、优先级、请求状态；OS 管理 | [[408/计算机组成原理/5.中央处理器/5.异常和中断机制.md\|异常和中断机制]] |
| **中断向量表/IDT** | 内存数据结构 | 存 ISR 入口地址；OS 建立，CPU 响应中断时查表 | 同上 |
| **通道程序/通道命令字** | 主存中的程序 | 由 OS 编写，通道硬件执行；CPU 只发启动命令 | [[408/计算机组成原理/7.输入输出系统/3.输入输出方式.md\|输入输出方式]] |

### 4.2 对应用程序员透明/不可见的 I/O 细节

- 设备的物理结构、寄存器地址、中断号、DMA 传送细节 → **对应用程序员不可见**。
- 应用程序通过**系统调用**（`read`/`write`/`ioctl`）使用设备，内核/驱动代替它操作端口、DMA、中断。
- 设备内部的机械/电气细节（磁盘寻道、SSD 磨损均衡、打印机电机）→ **对所有程序员透明**。

> [!note] 统一编址 vs 独立编址与"可见性"
> - **统一编址（MMIO）**：I/O 端口占用主存地址空间，用普通访存指令访问 → 端口"像内存一样"可见，但页表/MMU 可以对其做保护。
> - **独立编址**：端口有独立地址空间，需要专用 I/O 指令（x86 `IN`/`OUT`），通常是**特权指令** → 只有系统程序员可见。
> 出处：[[408/计算机组成原理/7.输入输出系统/2.输入输出接口.md|输入输出接口]]。

### 4.3 中断机制中的"可见"与"不可见"

| 元件/操作 | 可见性 | 说明 |
|---|---|---|
| **PSW 中的 IF 位** | 系统程序员可见（特权指令 CLI/STI） | 控制可屏蔽中断的全局开关 |
| **中断屏蔽字（IMR）** | 系统程序员可见 | 逐中断源屏蔽；由中断控制器管理 |
| **中断向量号** | 硬件/系统可见 | 异常向量号由 CPU 预定义；外部中断向量号由中断控制器提供 |
| **中断向量表/IDT** | 系统程序员可见 | 存 ISR 入口地址 |
| **中断隐指令** | 不可见 | 保存断点、关中断、查向量表等由硬件自动完成，无对应机器指令 |
| **中断响应过程** | 对应用透明 | 应用只看到程序被"打断"后恢复；具体保存/恢复由硬件 + OS 完成 |

> 出处：[[408/计算机组成原理/5.中央处理器/5.异常和中断机制.md|异常和中断机制]]、[[408/操作系统/1.计算机系统概述/3.操作系统的运行环境.md|操作系统的运行环境]]。

### 4.4 I/O 软件层次：越往下越"可见"

| 层次 | 实现者 | 能看到/操作什么 |
|---|---|---|
| **用户层 I/O 软件** | 应用程序/库函数 | 逻辑设备名、系统调用接口；看不到端口和控制器 |
| **设备独立性软件** | OS | 逻辑设备到物理设备的映射、缓冲区、SPOOLing |
| **设备驱动程序** | OS/驱动 | 端口地址、控制器寄存器、DMA 描述符 |
| **中断处理程序** | OS | 中断向量、状态寄存器、设备完成信号 |
| **硬件** | 设备控制器/设备 | 寄存器、电气与机械细节 |

> 结论：**"端口对谁可见"取决于你站在哪一层**——应用只看到逻辑设备，驱动才看到端口。出处：[[408/操作系统/5.输入输出管理/1.输入输出管理概述.md|输入输出管理概述]]。

## 五、ISA 与微体系结构：可见性的边界

> [!important] 核心结论
> **ISA = 程序员可见的抽象；微体系结构 = 对程序员透明的实现。**
> 同一 ISA 可以有完全不同的微体系结构（流水线级数、Cache 容量/关联度、分支预测、乱序执行），但二进制程序无需修改即可运行——这正说明微体系结构对程序员**不可见**。

### 5.1 ISA 中"可见"的内容

| ISA 规定的内容 | 是否可见 | 说明 |
|---|---|---|
| 指令格式、操作类型 | 可见 | 程序员直接使用 |
| 寄存器组织（GPR、PC、PSW 等） | 可见 | 数量、编号、位宽由 ISA 规定 |
| 寻址方式 | 可见 | 立即/直接/间接/基址/变址等 |
| 地址空间大小与编址方式 | 可见 | 由地址线/MAR 位数决定 |
| 数据类型与字节序 | 可见 | 整数、浮点、大小端 |
| 异常/中断机制 | 部分可见 | 异常类型、向量表结构由 ISA 规定；处理过程由 OS 完成 |
| **微程序/控存** | **不可见** | 实现细节，属于微体系结构 |
| **流水线/Cache/分支预测** | **不可见** | 性能实现细节 |

> 出处：[[408/计算机组成原理/4.指令系统/1.指令系统.md|指令系统]]、[[408/计算机组成原理/1.计算机概述/2.计算机系统层次结构.md|计算机系统层次结构]]。

### 5.2 程序 vs 微程序

| 维度 | 程序（机器指令） | 微程序（微指令） |
|---|---|---|
| 组成 | 机器指令序列 | 微指令序列 |
| 存放 | 主存 | 控制存储器 CM（ROM） |
| 编写者 | 软件程序员 | CPU 设计者 |
| 可见性 | **对程序员可见** | **对程序员透明** |
| 执行者 | CPU | 微程序控制器 |
| 顺序控制 | PC | μPC |

> 出处：[[408/计算机组成原理/5.中央处理器/4.控制器的功能和工作原理.md|控制器]]、[[408/计算机组成原理/1.计算机概述/2.计算机系统层次结构.md|计算机系统层次结构]]。

### 5.3 微体系结构中"不可见"的典型

- 数据通路的具体连接（单总线/多总线/专用通路）
- 控制器实现（硬布线 vs 微程序）
- 流水线级数、冒险检测、转发/停顿
- Cache 层次（L1/L2/L3）、容量、关联度、替换算法、写策略
- 分支预测、乱序执行、寄存器重命名
- TLB 结构、页表遍历硬件

> 这些都会影响**性能**，但不影响**程序语义**（在正确实现的前提下），因此对程序员透明。

## 六、不同程序员的可见性矩阵

> [!tip] 读表方法
> "可见"= 能通过指令/系统调用直接操作；"透明"= 由下层自动处理，无需也无法直接操作；"不可见"= 知道存在但无权/无法访问。

| 元件/结构 | 高级语言应用程序员 | 汇编程序员（用户态） | 系统程序员（内核） | 硬件设计师 |
|---|---|---|---|---|
| 通用寄存器、PC、PSW 条件码、SP、段/基址/变址 | 不可见（编译器分配） | 可见 | 可见 | 可见 |
| PSW 控制位（IF、模式位等） | 不可见 | 不可见（用户态） | 可见 | 可见 |
| IR、MAR、MDR、暂存寄存器 | 不可见 | 不可见 | 不可见 | 可见 |
| 页表/段表 | 不可见 | 不可见 | 可见 | 可见 |
| 页表基址寄存器（PTBR/PTR/CR3） | 不可见 | 不可见（用户态无权限） | 可见 | 可见 |
| 重定位寄存器/界地址寄存器 | 不可见 | 不可见（用户态） | 可见 | 可见 |
| TLB | 透明 | 透明 | 透明（软件管理 TLB 的架构例外） | 可见 |
| Cache | 透明 | 透明 | 透明（性能计数器可感知） | 可见 |
| 主存/虚拟地址空间 | 可见（虚拟地址中的变量） | 可见（地址/访存指令） | 可见（虚拟 + 物理） | 可见 |
| I/O 端口、设备控制器寄存器 | 不可见（经系统调用） | 不可见（用户态；内核态汇编可见） | 可见 | 可见 |
| DMA 控制器、中断控制器寄存器 | 不可见 | 不可见（用户态） | 可见 | 可见 |
| 中断向量表/IDT | 不可见 | 不可见（用户态） | 可见 | 可见 |
| 微程序、控存、μPC/μIR | 透明 | 透明 | 透明 | 可见 |
| 流水线、Cache 替换算法、分支预测 | 透明 | 透明 | 透明 | 可见 |

> [!warning] 408 默认约定
> 1. **TLB 由硬件管理**，对所有人透明；少数 ISA（如 MIPS 某些实现）采用软件管理 TLB，属于例外，408 不考默认前提之外的细节。
> 2. **Cache 完全由硬件管理**，对所有程序员透明；不要因为"性能分析"把 Cache 说成可见。
> 3. **页表基址寄存器**在计组中列入"用户不可见"，在 OS 中属于内核可见的系统控制寄存器——按题目问的"哪个程序员"作答。
> 4. 表中的"汇编程序员"按**用户态**处理；内核态汇编（OS/驱动）可执行特权指令，控制寄存器、I/O 端口等对他也可见——此时他的身份已接近系统程序员。
> 5. 内联汇编、编译器内建函数（intrinsics）、调试器可以"看到"寄存器/PC，但那是**借用汇编/调试视角**，不改变高级语言抽象层的可见性结论。

## 七、操作系统中的补充：可见 / 不可见

> [!note] 说明
> 这里的"元件"扩展到 OS 管理的数据结构与资源。判断标准仍是：**谁写代码管理它**。

| 对象 | 可见性 | 说明 | 出处 |
|---|---|---|---|
| **PCB（进程控制块）** | 对用户进程不可见 | 由内核维护，存于内核区；用户只能通过系统调用间接使用 | [[408/操作系统/2.进程与线程/1.进程.md\|进程]] |
| **页表、页表基址寄存器** | 对应用不可见，对内核可见 | OS 建立/切换页表；应用只见虚拟地址 | [[408/操作系统/3.内存管理/1.内存管理概念.md\|内存管理概念]] |
| **TLB** | 对应用透明 | 硬件加速地址转换；进程切换时刷新或用 ASID | [[408/操作系统/3.内存管理/2.虚拟内存管理.md\|虚拟内存管理]] |
| **PSW 模式位（用户态/内核态）** | 对应用不可见/不可改 | 由硬件在中断/异常/系统调用时切换；返回用户态需特权指令 | [[408/操作系统/1.计算机系统概述/3.操作系统的运行环境.md\|操作系统的运行环境]] |
| **中断屏蔽字、中断控制器** | 对应用不可见，对内核可见 | 内核管理中断优先级/屏蔽；用户态不能关中断 | 同上；[[408/计算机组成原理/5.中央处理器/5.异常和中断机制.md\|异常和中断机制]] |
| **文件标识符（inode 号）** | 对用户不可见 | 文件系统内部唯一标识；用户看到的是文件名 | [[408/操作系统/4.文件管理/1.文件系统基础.md\|文件系统基础]] |
| **文件物理位置（磁盘块号）** | 对用户不可见 | 由文件系统映射；用户使用逻辑文件 | 同上 |
| **用户级线程** | 内核对线程不可见 | 内核只把整个进程作为调度单位 | [[408/操作系统/2.进程与线程/3.CPU 调度.md\|CPU 调度]] |
| **系统调用实现细节** | 对应用透明 | 应用只看到 API；陷入、参数传递、内核栈等由库/内核处理 | [[408/操作系统/1.计算机系统概述/3.操作系统的运行环境.md\|操作系统的运行环境]] |

> [!tip] OS 中的"透明"高频例子
> - **分页对用户透明**：用户看到一维连续地址空间；分段不透明（程序员需显式划分段）。
> - **动态重定位对用户透明**：MMU 自动加基址；进程被移动也不感知。
> - **SPOOLing 对用户透明**：用户感觉独占设备，实际共享。
> - **虚拟存储器对应用透明**：缺页、调页由 OS 完成。

## 八、易混淆辨析总表

> [!important] 最关键的一条（先分清是谁）
> **汇编程序员 vs 应用程序员**：前者直接面对 ISA，可见寄存器、PC、PSW、地址；后者面对高级语言抽象，寄存器由编译器分配，看到的是变量、函数、虚拟地址空间。**408 说"对程序员可见"默认指汇编程序员**；说"对应用程序员透明"才切到应用视角。

| # | 容易混淆的一对 | 关键区别 |
|---|---|---|
| 1 | **可见 vs 透明** | "透明"在教材里 = **不可见/不用管**，不是"看得见"；可见 = ISA 暴露、指令可直接/间接操作 |
| 2 | **汇编程序员 vs 应用程序员** | 汇编程序员直接看 ISA（寄存器/PC/PSW/地址）；应用程序员只看编译器 + OS 的抽象（变量/函数/虚拟地址空间） |
| 3 | **PC vs IR** | PC 存**下一条指令地址**，转移指令可改，**可见**；IR 存**当前指令**，无指令可访问，**不可见** |
| 4 | **MAR vs MDR** | MAR 送**地址**、位数决定寻址空间；MDR 传**数据**、宽度通常等于存储字长；二者都**不可见** |
| 5 | **MAR vs 页表基址寄存器** | 都存地址：MAR 是本次访存地址（不可见）；PTBR 是页表基址（系统程序员可见） |
| 6 | **PSW 可见 vs 微程序不可见** | PSW 的条件码可被条件转移读取，**部分可见**；微程序/控存/μPC/μIR **完全透明** |
| 7 | **Cache vs 虚拟存储器** | Cache：纯硬件，**所有程序员透明**；虚存：硬件 + OS，**应用透明、系统可见** |
| 8 | **TLB vs 页表** | TLB 是页表的硬件 Cache，**透明**；页表是主存数据结构，**系统程序员可见** |
| 9 | **逻辑地址 vs 物理地址** | 应用只见逻辑/虚拟地址；物理地址由 MMU 转换，系统/硬件可见 |
| 10 | **机器指令 vs 微指令** | 机器指令对程序员可见；微指令是 CPU 实现细节，对程序员透明 |
| 11 | **可见 vs 可修改** | 条件码可读但通常不能直接写；IF 等控制位由**特权指令**修改；"可见"不等于"随便改" |
| 12 | **透明 vs 无性能影响** | Cache/流水线对程序员不可见，但**性能影响可见**；透明指"不用管"，不是"没影响" |
| 13 | **I/O 端口 vs 主存单元** | 统一编址下端口像内存一样可访问，但可能受 MMU/特权保护；独立编址需特权 I/O 指令 |
| 14 | **中断向量表 vs 中断隐指令** | 向量表是**内存数据结构**，系统程序员可见；隐指令是**硬件自动操作**，不可见 |
| 15 | **用户级线程 vs 内核级线程** | 用户级线程对**内核不可见**；内核级线程由内核直接调度 |
| 16 | **页表 vs 段表** | 页表对用户透明；段表/分段**不透明**（程序员需显式划分段） |

---

## 九、30 秒判断流程

> [!important] 遇到"是否对程序员可见"的选择题
> 1. **先问是谁**：题目说的是**汇编程序员**（默认）还是**应用程序员**？汇编程序员可见寄存器/PC/PSW/地址；应用程序员只看到变量/函数/虚拟地址空间。
> 2. **再分类**：寄存器？存储器？I/O 端口？还是 OS 数据结构？
> 3. **查 ISA**：有没有指令能直接编码/访问它？有 → 可见；没有 → 透明/不可见。
> 4. **再分层**：机器指令层 → 可见；微指令/硬件层 → 透明。
> 5. **最后看权限**：用户态指令能访问 → 汇编可见；只有内核/驱动能访问 → 系统可见；只有硬件设计者能改 → 透明。
> 6. **排除法**：IR、MAR、MDR、暂存、μPC、μIR、CM、Cache、TLB、流水线、微程序 → 一律"不可见/透明"；PC、GPR、PSW、SP、段/基址/变址 → 可见；页表、PTBR、I/O 端口、DMA/中断控制器 → 系统可见。

---

> [!quote] 复习口诀
> **先分人**：408 默认问汇编程序员；应用程序员只看到编译器 + OS 的抽象。
> **可见看 ISA，透明是"不用管"。**
> **寄存器**：通用、PC、PSW、SP 可见；IR、MAR、MDR、暂存、μPC、μIR 透明。
> **存储**：Cache、TLB 全透明；虚存应用透明、系统可见；页表、PTBR 系统可见。
> **I/O**：端口、DMA、中断控制器、向量表系统可见；设备内部细节全透明。
> **微架构**：流水线、Cache 算法、分支预测，只有硬件设计师可见。
> **一句话**：谁写代码管它，它就对谁可见。

> [!summary] 最后总结：汇编程序员 vs 应用程序员
> - **汇编程序员看得见"机器"**：寄存器、PC、PSW、SP、内存地址、寻址方式；能直接控制程序在硬件上的执行。
> - **应用程序员看得见"问题"**：变量、表达式、函数、对象、文件、进程/线程、虚拟地址空间；寄存器和 PC/PSW 由编译器与 OS 代管。
> - **408 默认问的是汇编程序员**；只有题目明说"对应用程序员透明"时，才切到高级语言抽象层回答（Cache、TLB、分页、虚存等）。
